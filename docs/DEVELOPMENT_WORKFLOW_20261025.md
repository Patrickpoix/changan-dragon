# 开发工作流（2026-10-25）

> 日常开发的标准流程。

---

## 一、每日流程

### 早上
1. 看Issues列表
2. 选要做的任务
3. 创建分支
4. 开始开发

### 开发中
1. 小步提交
2. 频繁测试
3. 写注释
4. 保持专注

### 收工前
1. 提交代码
2. 推送到远程
3. 写明日计划

---

## 二、Git工作流

### 分支策略
- main：主分支，稳定
- feature/xxx：功能分支
- fix/xxx：修复分支

### 提交规范
```
feat: add npc system
fix: fix water shader bug
docs: update readme
refactor: refactor asset loader
```

### PR流程
1. 推送分支
2. 创建PR
3. 等待审查
4. 响应反馈
5. 合并

---

## 三、代码工作流

### 开发新功能
1. 先看设计文档
2. 写设计草稿
3. 写代码
4. 测试验证
5. 写文档
6. 提交PR

### 修复Bug
1. 复现Bug
2. 定位问题
3. 修复代码
4. 验证修复
5. 提交PR

### 优化性能
1. 测量性能
2. 找瓶颈
3. 优化代码
4. 验证效果
5. 提交PR

---

## 四、素材工作流

### 找素材
1. 确定需要什么
2. 搜索免费CC0素材
3. 下载验证
4. 分类整理
5. 更新索引
6. 提交PR

### 整理素材
1. 检查质量
2. 分类命名
3. 压缩优化
4. 更新索引
5. 提交PR

---

## 五、文档工作流

### 写设计文档
1. 确定主题
2. 收集资料
3. 写草稿
4. 审查修改
5. 提交PR

### 更新文档
1. 发现过时
2. 更新内容
3. 提交PR

---

## 六、测试工作流

### 功能测试
1. 写测试用例
2. 运行测试
3. 修复失败
4. 全部通过

### 视觉测试
1. 看效果
2. 对比参考
3. 调整优化
4. 验收通过

---

## 七、发布工作流

### 准备发布
1. 检查清单
2. 更新版本
3. 更新changelog
4. 构建测试

### 发布
1. 部署上线
2. 验证访问
3. 发布公告

### 异步沟通
- GitHub Issues
- GitHub Discussions
- 邮件

### 同步沟通
- 定期会议
- 临时讨论
