# 开放世界技术架构设计（2026-10-25）

> 84平方公里开放世界，流加载、LOD、性能优化是核心技术挑战。

---

## 一、引擎选型

### 选定：Three.js r169
- **理由**：包体最小、现有代码零迁移、生态成熟
- **gzip主包**：162KB
- **Streaming POC**：已验证500m chunk + 4级LOD

### 排除项
- Babylon.js：包体大（433KB gzip）、迁移成本高
- PlayCanvas：闭源SaaS绑定
- Godot：WASM太大（5-10MB）、启动慢
- PixiJS：2D引擎，不适合3D

---

## 二、流加载系统

### Chunk分块
- **大小**：500m × 500m
- **数量**：全城约360块
- **格式**：GLB + 纹理图集

### 加载策略
| 距离 | 加载状态 | LOD等级 |
|---|---|---|
| 0-250m | 常驻 | LOD0 |
| 250-500m | 常驻 | LOD1 |
| 500-1000m | 预加载 | LOD2 |
| 1000-2000m | 远处加载 | LOD3 |
| >2000m | 卸载 | 无 |

### 双缓冲
- 3×3 = 9块常驻
- 7×7 = 49块预加载
- 玩家移动时动态加载/卸载

---

## 三、LOD系统

### 4级LOD
| 等级 | 面数 | 用途 |
|---|---|---|
| LOD0 | 完整 | 近景，高精度 |
| LOD1 | 50% | 中景，中精度 |
| LOD2 | 20% | 远景，低精度 |
| LOD3 | 5% | 超远，impostor |

### 优化手段
- Draco压缩
- Meshopt优化
- KTX2纹理压缩
- InstancedMesh合批
- 距离裁剪

## 四、性能预算

### 桌面端目标（16英寸笔记本）
- 帧率：60fps
- 可见三角形：150万
- DrawCall：<300

### 优化优先级
1. InstancedMesh（合批）
2. LOD分级

4. 纹理压缩
5. 几何简化

## 五、NPC系统

### 规模
- 朱雀大街峰值：500人
- 全城上限：800人
- 普通坊：50-100人/坊

### 技术实现

## 六、建筑生成

### 策略
- **A类地标**：14个手工精模（大明宫、大雁塔等）

### 差异化

- 按坊类型选择建筑组合
- 不同材质/颜色/植被
