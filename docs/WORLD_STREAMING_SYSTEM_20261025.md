# 大世界流加载系统详细技术设计

> 创建时间：2026-10-25

---

## 问题
唐长安城84km²（9721m × 8652m），不可能一次性加载所有模型。
需要：走到哪加载哪，走远了卸载。

## Chunk切分方案

### 网格划分
- 每块 **500m × 500m**
- 横向: 9721/500 ≈ 20块
- 纵向: 8652/500 ≈ 18块
- **总计: 360个chunk**

### 坐标约定
- 原点(0,0): 西南角（明德门西侧）
- X轴: 东为正
- Z轴: 北为正
- chunk索引: `(x=Math.floor(worldX/500), z=Math.floor(worldZ/500))`

## 加载策略

### 常驻chunk（3×3 = 9块）
- 玩家所在chunk + 周围8个
- 这9块始终在内存中
- 玩家移动时，新进入的边块加载，离开的边块卸载

### 预加载chunk（7×7 = 49块）
- 在常驻范围外，后台预加载
- 玩家快速移动时不会卡
- 低优先级加载，不阻塞主线程

### 卸载策略
- 距离 > 3个chunk（1500m）的chunk卸载
- 先释放GPU资源（几何、贴图），再释放JS对象
- 双缓冲：新chunk加载完成后才卸载旧的

## Chunk数据格式

每个chunk包含：
```json
{
  "chunkId": "x_z",
  "buildings": [...],
  "npcs": [...],
  "trees": [...],
  "props": [...],
  "groundTexture": "grass",
  "water": false
}
```

## LOD系统

### 距离层级
| 距离 | LOD | 渲染方式 |
|---|---|---|
| <100m | LOD0 | 精模（5k-20k面） |
| 100-300m | LOD1 | 中模（1k-3k面） |
| 300-800m | LOD2 | 低模（200-500面） |
| 800-2000m | Billboard | 2面片公告板 |
| >2000m | 雾隐 | 不渲染 |

### 建筑LOD
- LOD0: 完整建筑（屋顶+墙体+门窗+台基）
- LOD1: 简化建筑（少细节，合并网格）
- LOD2: 盒子近似（只保留轮廓）
- Billboard: 一张贴图

## 性能预算

### 内存预算
| 资源 | 预算 |
|---|---|
| 几何内存 | <512MB |
| 贴图内存 | <1GB |
| 音频内存 | <256MB |
| JS堆内存 | <512MB |
| **总计** | **<2.3GB** |

### 帧率预算
| 平台 | 目标帧率 |
|---|---|
| 桌面RTX 3060+ | 60fps |
| 桌面GTX 1660 | 45fps |
| 笔记本/核显 | 30fps |

### DrawCall预算
- 桌面: <200 DrawCall
- 笔记本: <150 DrawCall
- 通过InstancedMesh合批实现

## 压缩策略

### 几何压缩
- Draco压缩：几何数据压缩到原始的20-30%
- Meshopt：运行时解压

### 贴图压缩
- KTX2 Basis：跨平台压缩纹理
- 分辨率：精模2K，普通1K，远景256

### 网络加载
- 只加载玩家附近的chunk
- 后台预加载
- 优先级：当前chunk > 相邻chunk > 预加载

---

*360个chunk，每个chunk平均约100个物体，通过合批和LOD控制在200 DrawCall以内。*
