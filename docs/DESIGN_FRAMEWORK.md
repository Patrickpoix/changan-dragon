## 1. 创作方向与历史边界

要让玩家作为一只小青龙，走进一座有宏大秩序、细腻生活和自然呼吸的盛唐长安。欣赏是主循环：看见有吸引力的地方 → 自由前往 → 进入/登临/绕行 → 观察人物与经营活动 → 换角度欣赏 → 继续游览。步行、木车、飞行服务于这个循环；不增加必须比赛、刷任务或战斗的负担。

采用《长安三万里》日常三维场景的温润体积、木构层次、服饰剪影、明暗与空气感，结合用户已认可的三张分区概念。借鉴《大理寺日志》的院落组织、屋顶剪影与色块关系；该片主要背景为武周洛阳，城市地图不移植到长安。没有取得影视模型或素材授权。

时间气氛以开元、天宝盛唐为中心，作为艺术化游览世界；不承诺某一年每栋建筑都精确复原。佛光寺东大殿（857）、南禅寺大殿（782）可帮助研究唐木构，均晚于这个时间气氛，不能把它们整栋复制后称为当时长安的实测建筑。文物、复原图、影视设计和本项目幻想要分别标注。

- 保留长安可识别的关系：南侧明德门、中轴朱雀大街、北侧皇城/宫城、东北大明宫、东部兴庆宫、东西市、东南慈恩寺与曲江、里坊和有门的院落。
- 地图为艺术化压缩，人物、门窗、廊道和台阶采用人体尺度，坊间距离压缩。不能把整座城等比例缩小成玩具，也不能把宏阔天街全改成市集窄巷。
- 现有坐标北为负 Z：外郭约 X[-450,450]、Z[-380,380]，大明宫向北外伸。先保留可恢复的坐标与景点 ID，再以布局数据渐进替换；这是现有游戏尺寸，不是历史地图测量。
- 不规定未经核实的“精确108坊复原”。坊数随时期与统计口径有区别；普通坊先有类型、入口、道路和完整院落，再核实历史名称。
- 小龙、无翼飞行、木自行车与自由夜游属于有意的幻想。唐代市坊夜禁作为背景知识，不做封门惩罚。概念图里的辣椒状挂货、过晚家具/装饰、错误汉字不能因画得好看就照搬。
- 主街以有排水与车辙的压实土路为基底；重要门前、台阶、院落和部分铺面采用砖石。不是全城统一现代石板步行街。避免将江南水乡河网、清式黄瓦/密彩画、日式鸟居/注连绳当作唐长安通用元素。

## 2. 城市空间与地区体验

全城共享真实三维地形、建筑和路径。以下不是八张背景画，也不是互相断开的拍照舞台。首次制作以原有八处景点为锚，增加坊巷与院落作为连接空间；各区均可从地面、侧后方和空中欣赏。

| 地区 | 空间与主景 | 近景生活及可到达处 | 构图/声音/资源重点 |
| --- | --- | --- | --- |
| 明德门及入城段 | 厚夯土城墙、真实门洞、门楼、城内外道路高差和远望中轴 | 守门、赶车、行旅整理行装；穿门、登可开放城楼平台、看城内屋海 | 先暗门洞再见亮街；门楼与城墙完整背面；木轮、蹄声、远市声 |
| 朱雀大街 | 开阔直街、沿街坊墙与坊门、侧渠、远处皇城门 | 行人分组、骑者、运货队列、路口驻足；通过坊门进入较小街巷 | 宏阔透视与低平屋海衬托地标；不沿全轴重复放后世牌楼 |

| 兴庆宫苑 | 龙池、环岸园路、亭与花木、楼阁相互借景 | 赏花、抚琴/交谈、临水停步、园中游船；亭台/步桥可达 | 更轻、疏、柔的木构和树冠，花色集中成组，不做满地均匀花点 |
| 慈恩寺及雁塔 | 寺门、庭院、殿与砖塔的高低序列，低视角见塔 | 钟声、安静人流、香具与院树；绕塔、廊下行走、登开放平台 | 土黄砖塔、灰瓦、深木、较克制朱红；不是把寺庙换成带尖顶的楼 |
| 曲江水岸 | 曲岸、前后水湾、开合园路、桥、临水廊、码头和亭楼 | 食摊/酒肆、倚栏、候船、船夫摇桨、画舫缓行；步道—码头—停泊船连续可走 | 岸有高度/坡度与湿润过渡，水中有岸影/船影和局部波光；不放海船或现代观光艇 |

每区至少设计“抵达—进入—停留—回望”四种空间。首条代表路线为**西市坊门 → 胡饼/织物街段 → 酒肆一层 → 楼梯/楼廊 → 后院 → 飞起回望市区**；水岸和宫苑分别另做完整代表路线。不是做完这一条就宣布全城完成。

### 街段构图约束

- 人眼近景先有连续街界：墙/门/铺面/廊柱交替；使用空隙引导到院落，避免零散房屋围着巨大空地。
- 近景物约0–8m、中景营业/行人约8–35m、远景屋海/地标35m外，仅作为布景检查分层，不作为硬裁剪界限。
- 市集内街通路起点约6–9m，坊巷约3–5m，商铺退廊约1.8–2.5m；朱雀大街维持明显更宽的等级。均为初始游戏尺度，需要镜头/会车/通行试片校准。
- 同街有一层、两层与少量楼阁的节奏，屋脊朝向、檐口、门面与树冠组合变化；不能只随机缩放同一栋房屋。
- 摊位位于经营带，人流、车队和主角各有连续余量；镜头避障与构图数据同步。道具不能占据台阶、楼梯、门洞和视线焦点。

## 3. 建筑资产系统：从完整类型到共享构件

先做完整类型的比例、轮廓与空间，再抽出共享构件。以“墙盒+统一绿色屋顶+贴斗拱”继续扩建的路线停止。现有三开间木构样板用于研究结构，不作为全城合格模板。

| 类型族 | 必须包含的完整结构与空间 | 初始变体设计与改造方向 |
| --- | --- | --- |
| A 民居/作坊 | 台基、柱/墙、前廊、真实门窗、侧后墙、完整四向屋顶、院门/院墙接口 | 单/双/三开间，小院与作坊两种进深；单坡附屋不随意拼出穿插檐口 |
| B 单层店铺 | A的完整结构 + 真实柜台、门板/窗板、货架、遮篷、后部工作区 | 食、布、陶、药、笔墨五种经营套件；外墙与后院也成立 |
| C 双层酒肆/楼店 | 完整楼板、楼梯、退廊、扶栏、柱梁支承、腰檐、檐下空间和可停留室内 | 两/三开间、转角入口、端头店；避免腰檐侵入楼廊、上层无交通 |
| D 廊/亭/步桥 | 柱网、梁椽、顶壳/瓦、踏步、地板、栏杆、转角与端部构造 | 直廊/转廊、方亭/多边亭、岸亭/水亭；转角完整，背面不省略 |
| E 门/墙 | 收分夯土、薄石基、压顶、实际洞口、门扇、门楼与道路连接 | 坊门/宫门/城门的等级与规模分别设计；城门不套清代城楼 |
| F 殿堂/楼阁 | 柱网/台地/阶道/斗拱/梁椽/屋面同源，前后侧廊、内部可见空间完整 | 普通殿、主殿与门阙分别设计；屋顶类型按证据选择，不让每栋都重檐 |
| G 塔寺/地标 | 基座、逐层收分、门窗洞口、塔身与檐口、寺院环境和正确接地 | 砖塔与木楼分开制作，非把同一楼层等比叠高 |

共享构件包括柱/枋/梁、受类型约束的斗拱、椽、檐口、不同屋顶壳、瓦垄/垂脊、门窗、栏杆、楼梯、台基、院墙。构件连接由柱网、开间、进深、檐口标高与插接点定义，禁止任意非等比拉伸导致承重、圆角和瓦距失真。

**造型准则：** 屋顶低阔有重量，脊/坡/檐口与结构同源；屋顶壳有厚度，侧坡也有瓦流；轻微檐起服务于类型，不用夸张上翘表达所有“国风”。柱梁有有意的边缘圆润与端部形态，不能每条边都等幅倒角。普通房屋灰青瓦、土白灰泥与自然/漆木为主，朱红/青绿/金色按等级与构图使用。檐下存在真深度与接触阴影，四面与俯视均成立。

## 4. 小龙、木车、人物与动作

### 小龙与木车

以 [市集](concept-market.png) 的可爱脸形和 [曲江](concept-qujiang.png) 的无翼飞行形态为外观依据。本轮已生成并实际查看 [小龙正侧背/走骑飞设计研究](concept-dragon-turnaround.png)，补充背鬃、尾根、侧脸、骑行握点与无翼飞行方向。**这是尚未经过用户新确认的辅助研究图，不是已建成网格或精确工程三视图**；仍需按下表修正并在三维中校准。

| 新研究图检查项 | 图中可用设计 | 不可照搬的问题/下一步约束 |
| --- | --- | --- |
| 脸/身形 | 玉青/奶白/暖眼睛、短吻、眼睑、连续颊部、轻围巾，正侧背有明确主形 | 仍须做真实眼窝/嘴腔/关节拓扑与表情；图中密鳞不能全部成为独立高细节几何 |
| 比例 | 小于成人的方向正确，角/鬃/尾有主次 | 右侧1.25/1.7m标尺与剪影比例并不严格一致，**以本文米制起点和三维尺校准，禁止用图中尺标测量** |
| 骑行 | 可读握把/坐垫/双轮与小龙骑姿 | 曲柄/脚踏/传动与腿长未构成可靠机械图，需具名接口、真实曲柄长度与脚踏循环约束；不能照生图生成穿插车架 |
| 飞行/背面 | 无翼伸展、尾鬃与围巾形成流向 | 不同视图鳞列/角细节不完全同源；制作时以同一连续网格统一，明确尾根与围巾安全包络 |

- 连续头脸：眼窝包住眼球，有上/下眼睑和眉弓；鼻吻、嘴角、下颌连为一体。三分之四仍可爱，不能外挂球眼/球鼻。
- 连续躯干与四肢，清晰肩髋与尾根；背鬃、角、耳、腹甲与少量鳞片有主次。玉青大色块、暖奶白腹部、少量暖金/红围巾，避免全身金属/翡翠反射。
- 工程起点：小龙脚到头顶约0.95–1.10m，含角约1.20–1.35m；成人约1.65–1.80m。不是历史数据，不直接把当前2.20m小龙缩小就结束，必须连同脸部/肢体、车、碰撞、步高和镜头重做。
- 木车轮径起点0.45–0.55m；榫接/木纹方向、轮毂/车轴/辐条、座垫、把手、曲柄与脚踏连贯，有少量必要金属连接。不能直接把19世纪博物馆木车缩放称为唐代史实。
- 握点/脚踏/鞍座/根骨位置为具名接口；手脚随车与踏板运动。走路有落脚与重心，飞行无强行加西式翅膀，身体/尾部/围巾形成流线，不能整只静态模型上下漂浮。
- 必备动作：待机/左右观察/眨眼/微笑、慢走/快走/转身/停步、上车/骑行/停车/下车、起飞/巡飞/转弯/悬停/降落。模式切换的车显隐有过渡；表情不依赖强制玩家打开对话。

### 城中人物

**用户最新纠正：唐人是自然人体与脸形，古今无本质区别；不以夸张脸型/头身表达时代或电影感。** 已撤回Snow/Rain夸张头脸作为项目基准，保留其原件仅作绑定/拓扑研究。采用自然成人基体/正常眼球尺寸，唐代差异主要在发式、服饰、妆容和身份装束。早期“5.5–6.5头身”“电影化重塑脸形”等建议不得继续执行。

先完成同风格男女基体与脸部系统，再制作普通居民、店主/小贩、商旅、文士、侍者、守卫、船夫等服装与活动族。年龄、体型、发式和脸形变化来自少数有设计的完整原型；不靠随机颜色把同一圆锥袍当成所有阶层。

- 人物保持自然人体与五官比例，不放大头眼；约6.8–7.8头身只作松散检查参考，头颈肩、肘袖、腰带与衣身、膝/鞋有连续关系。与主角同场看轮廓，避免写实脸+低模衣服+Q版龙互相冲突。
- 唐服按具体类别研究：圆领袍/襕衫、襦裙/披帛、劳动短衣与裹腿、适当幞头/发髻、护卫服。宽袖随身份与工作区分，不把所有汉服统称唐服。
- 可用 MakeHuman/MPFB 的明确CC0核心基体与骨架帮助拓扑/变形，保持自然比例和脸部结构，调整个体特征、发式与服装；没有成熟唐服成品或绑定就不能声称人物已就绪。外部社区衣物逐件许可，不能继承核心CC0。
- 近景人物真实骨架/面部表情，衣服主要褶皱进入几何。中景可减骨/减面与错开动作相位，远景保留立体轮廓；不使用面对相机的人物贴片。

### 市井活动系统

每个铺面/活动点具备站位、手部目标、道具接口、候位、通路及声音范围。动作由状态与路径驱动，不让所有人不停绕圈。

| 活动 | 可见的动作与物件联系 | 空间/声音约束 |
| --- | --- | --- |
| 胡饼/汤食 | 整理面团/递食/端碗，火具、案台、蒸汽与食物有位置关系 | 不出现辣椒、玉米、土豆等后传常见食品；近处可听短句，远处混入市声 |
| 布帛 | 展开/卷起布匹、顾客看布、挂样轻动 | 布不是全部贴在墙上的色板；工作面和观众站位错开 |
| 香药/珠货 | 称量、开合盒、指示货物 | 器物是可识别形状，非全摊相同圆罐 |
| 茶酒/客栈 | 侍者端送、坐客交谈、栏边观望 | 桌凳高度/手臂位置统一；不用后世整套家具原样替换 |
| 行旅/商队 | 结伴行走、停靠、卸货、牵马/骆驼 | 牵引和货物不穿人/墙，双峰驼优先选型；主通路留宽 |
| 船夫/游人 | 划桨、靠岸、候船、倚栏 | 桨入水、船吃水、码头高度和人脚位置同源 |

店铺经营是场景体验，不必引入货币/购物经济系统。可短暂驻足、触发招呼/闲谈；诗笺仍可选。

## 5. 园林、水岸与舟船

先做地形和大轮廓，再种树与放石。柳树为垂枝与长叶簇，松树为有方向的枝盘，花树为枝干+成组花冠；不是给同一球形树冠换色。保留通路、坐观空间和向地标的视线。

- 植被组：街树、垂柳、松、花树、低灌木/地被、荷/芦苇；不同场景选择不同组合，不把同一套扫描草铺满全城。
- 近树有弯曲主干、合理分叉与不均匀冠簇，叶片材质与树皮分离。EZ-Tree可在独立较新Three工具环境生成GLB，输出到现有引擎，不把其新版本依赖直接塞入r160。垂柳仍需专门树形与长枝设计，工具没有“唐风”按钮。
- 石岸、泥岸、草坡、码头石基与台阶按岸线类型组织，水下延续、湿润线和根部接地成立。干路不等于均匀贴一张草地；夜景保留暗处，倒影不过度发光。
- 三种舟船分别设计：敞口小舟、带轻篷游船、完整可上船画舫。船壳中空、有舷厚/舭部/吃水，甲板、舱、顶、栏杆、家具和人物协调；画舫不是在小船上叠一间不相称大屋。
- 画舫需要侧面、俯视、艏艉与舱内设计。候选现代旅游画舫的灯串/设备/装饰不能原封照搬。海上帆船、龙舟竞渡船不代替湖上赏景画舫。
- 本轮已生成并实际查看 [完整画舫设计研究](concept-barge-study.png)：四分之三、侧面、去顶俯视舱内与端部，单层舱/前后甲板/长凳/柱梁/内走道。它沿认可曲江概念的暖木灰青瓦与少量金饰，**不是唐船考古图、精确剖面或已取得的3D模型**。图中装饰/屋顶仍需历史与结构校准，侧舷登船口不够明确，各视图柱距/坐具/艏艉细节并不严格一致，需统一参数重做，不能逐图拼出不同的船。
- 画舫三维起点约12m长/3.6m宽，舱内净高约2.1–2.3m、中央可走宽度至少1.0–1.2m；码头侧设明确活动舷门和水平搭板，栏杆与通行开口同源。吃水先在负载/水线试片中定，不能从生图地面阴影推断。较小轻篷船与小舟另有尺寸/类型，不能都缩放同一画舫。
- 船路满足岸线、转弯、桥洞净空、交会和停泊；登船碰撞与视觉甲板一致。移动船乘坐需独立完成随船位移、上/下船与安全回岸，不能用现有“能走上停泊船”冒充已完成搭乘。

## 6. 材质、色彩、日夜与电影镜头

### 统一表面语言

采用风格化PBR：大形与大色块清楚，材质有真实差别，细节经过筛选，不使用全城硬分段toon或粗描边，也不直接拼扫描材质。

初始调色方向：瓦为灰青/炭灰，木为暖褐/赭红，灰泥为土白/米灰，石为温灰，远景逐层偏冷，小龙保留玉青焦点。概念图是受光后的画面，不能直接把照片像素当物理baseColor。材质色与照明需要中性试片联合校准。

| 表面族 | 几何与材质承担的任务 | 资源筛选与加工 |
| --- | --- | --- |
| 瓦/屋面 | 屋面和近檐瓦流为几何；远处微起伏进入法线，不能省掉完整侧坡 | 现有Clay Roof Tiles02可用法线/粗糙；普通瓦不做镜面绿色塑料 |
| 木/漆木 | 梁端、柱脚、接缝和重要边缘有形体；木纹方向随构件 | Fine Grained Wood弱细节、Dark Wood只选合适部分；清除预烘焙强光/过黑纹理 |
| 灰泥/夯土 | 收分、转角和台基为几何；细表面和克制夯层另做 | 现有Clay Plaster/White Plaster可续用，避免挖掘土壁的大裂缝 |
| 路/石基 | 高差、排水、阶沿、车辙/接缝需读出，地面大形平稳 | 土路与砖石分区；Grey Stone Path是杂形石路候选，不能当全城铺装 |
| 布/丝绢 | 袖摆、衣身、遮篷褶皱形成轮廓，织纹是微表面 | 现有织物normal/ORM；新Fabric081C候选需校验文件。毛圈/粗针织、格子餐布不作为唐丝绸 |
| 陶/釉/金属 | 胎体口沿、器腹和把手有厚度；釉的粗糙、色彩与金属分开 | 既有陶锅与博物馆CC0唐器参考；不能把现代青花/品牌器具加入唐摊位 |
| 皮肤/龙体 | 主形、眼窝、眼睑和嘴角先成立；皮肤温润、腹甲/角略有不同 | 合理粗糙与微色变，必要烘焙，避免用高光掩盖接缝 |

资产先在同一中性棚检查灰模、日光材质和尺度，再看场景。使用物理UV、共享trim/图集、少量有意风化；避免每个梁柱/瓦片独立材质。AO只表达近接触，不能把同一方向的阳光烘进颜色后再转日夜。

### 光照与镜头

- 先锁晴日下午日光样片，再校准清晨、黄昏、夜间四种色彩脚本；白天应能读出檐下暗部，夜晚灯与暗水有对比，不能全画面均亮。
- 保留现有ACES、环境光和质量回退基础；先修模型与材质再调后处理。SAO/Bloom/实时倒影为增强，手机低档也要有正确大形、受光和接地感。
- 默认第三人称提供清楚路面与前方空间；起点跟随距离约3–5m、看向约0.7–1m高，须随新龙尺寸实测。侧拍、较高俯视、自由环视与电影模式共用安全避障，禁止相机穿檐梁。
- 步行更近、骑行略后、飞行随速度平稳拉开；不靠大广角让建筑变形，不强制自动转镜抢走拖动控制。仰望殿堂要保留前景尺度参照。
- 电影镜头是可暂停、可退出的真实场景运镜；路径避开树冠/檐口/人头，飞越屋顶时城市侧后方仍完整。景深/运动模糊只考虑可关闭的留影增强，不妨碍正常游览。

## 7. 引擎、模块与交付决策

| 层 | 本轮决定 | 原因及边界 |
| --- | --- | --- |
| 运行引擎 | 继续锁Three r160与现有MIT addons | 已有可玩的静态/离线、WebGL1兼容、蒙皮和后处理；美术问题不因迁移自动解决。Babylon/PlayCanvas/Godot已查主源，未发现必须迁移的实测理由 |
| 制作工具 | 现有Blender为主；MPFB/MakeHuman核心基体、EZ-Tree和Material Maker作选择性离线工具 | 输出可编辑源、GLB与纹理；代码许可与输出资产许可逐项分开。工具不直接进入运行包 |
| 优化 | 优先glTF Transform、meshoptimizer离线去冗余/重排/简化；纹理图集/压缩单独评估 | 减面不能破坏脸、轮廓、权重和屋脊；压缩字节不等于降低显存。引入解码器前验证单HTML与WebGL1回退 |
| 空间查询 | 先保留现有简化碰撞/网格索引；复杂地形/镜头查询可试three-mesh-bvh 0.7.6 | 已核对该版peer three>=0.151；不用最新版隐式升级引擎。不对每个装饰三角形做人物刚体 |
| 人群路径 | 先用具名通路、活动节点和静态障碍；复杂院落再评估Recast Navigation JS | Recast为WASM端口，需本地初始化/打包和上游通知核验。不是把库加入后人群就会经营/交谈 |
| 动画 | GLTFLoader + AnimationMixer/SkeletonUtils与轻量状态机 | 保留原动作授权、每角色独立骨架；不为普通走骑飞引入大型角色框架/全城布料物理 |
| 水/植被 | 保留实际岸线和船道，按新模型改材料/布置/轻量风动 | 真3D轮廓、岸线与通行共享数据；不采用扫描背景/高斯泼溅代替可进入城市 |
| 发布 | 静态网页优先运行入口，继续维护完整单HTML离线包 | 资源本地、无运行时平台账号/API/CDN。HTTP断网验证与手机本地文件验证分别记录 |

Godot当前Web导出需要WASM+WebGL2，只支持Compatibility路径，不支持把原生Forward+/Mobile效果直接导出；多线程还有隔离头要求，官方推荐的单线程导出也不等于没有WebGL2要求。Babylon/PlayCanvas具备成熟能力，但替换将重做现有场景接口、材质、交互和交付验证；本轮没有进行这些迁移或性能对比。Unreal原生预览的Lumen/Nanite/Groom/Chaos/PCG不当作浏览器可直接获得的效果；UE专用包必须有可用导出资产与重新烘焙/绑定方案。

## 8. 资产合同与高效整合管线

每个资产族有一份可复现合同，先通过合同再放入城市：

1. **来源：** 原作者/固定版本、原网址、逐文件许可、取得方式、SHA256；来源图仅研究的不得混进游戏。付费/Standard许可不允许把原始资产作为公共素材库直接提交。
2. **源与运行分开：** 保留可编辑源/构建脚本、原始许可证及派生记录；运行模型另存。源文件、研究样板、已采用运行资产分别计数。
3. **坐标：** 统一米制、GLB Y向上，明确面朝/原点、地面或水线基准、接合点。MakeHuman原始文件尺寸必须先测量并转换，不能假设OBJ自带米制。
4. **几何：** 连续主轮廓、有限顶点/法线、正确平滑与切线、无穿插漏面；建筑四面/屋顶/檐下和角色变形检查。剔除人台/辅助体/隐藏内部几何。
5. **材质：** 有限共享材质、物理UV与图集；区分sRGB颜色与线性normal/ORM，OpenGL法线；不靠双面材质掩盖所有反面错误。
6. **层级：** LOD0/1/2保持关键轮廓与接口；碰撞简模、可走面、楼梯/门洞/船甲板/角色附件为具名数据，与视觉源共同更新。
7. **动作：** 骨架/权重/动画/表情、循环接缝和根运动策略明确；检查脚滑、握点、衣服/尾部穿插、WebGL1骨纹理与阴影。
8. **布置：** 场景按地区→街段/院落→建筑/经营单元组织；同一布局数据输出视觉、碰撞、导航、电影机位和地图，避免五套坐标各自漂移。
9. **验证：** 棚内中性光与灰模 → 代表性真实场景 → 移动/侧后/飞越 → 手机尺寸/兼容 → 离线。每轮有对照截图和待修清单。

## 9. 手机预算与规模策略

以下是新样片的**待测预算**，不是当前游戏已经达到的性能。现有视图曾记录数百至上千绘制，需在正式扩展前降到可控规模。仅减少下载字节不能解决每帧绘制/蒙皮/透明过绘。

| 项 | 流畅档初始预算 | 精致档初始预算/补充 |
| --- | --- | --- |
| 目标体验 | 对目标真机争取稳定30fps，控制卡顿与发热 | 可提升阴影/倒影/后处理；真机实测后定默认档 |
| 主要颜色通道 | 可见三角形约50–80万，绘制约150–220次 | 约100–160万，绘制约250–350次；额外通道单独统计 |
| 可见人物 | 近景约12–20套完整蒙皮，其余按距离降面/降骨/错相 | 不把192个独立高细节角色全屏更新作为需求；远景仍需立体人形与活动节奏 |
| 普通店铺LOD | L0约1.2–2.5万面，L1约0.3–0.8万，L2约0.05–0.15万 | 大型酒肆/主殿单独预算；当前7.3万面木构研究样板不能直接铺满全城 |
| 主角/人物 | 小龙约3–4.5万面；近NPC约0.8–1.5万面，少量共享图集 | 人物从脸与衣服变形决定减面，不把预算当强制切掉表情的理由 |
| 植被 | 近冠簇有体积，远树保留3D冠形；控制alpha重叠和阴影范围 | LOD必须保持树种与冠形，不以远树都变球替代优化 |
| 纹理/显存 | 共享1k为主，512用于小物；估算纹理驻留≤96MiB，总GPU资源≤192MiB | 更高档另测，不能从PNG/GLB大小推断显存；1024 RGBA含mip约5.33MiB |
| 包/内存 | 完整离线包初始目标≤45MiB；按区域延迟解码/激活 | Base64会膨胀约1/3，含全城数据不等于开场同时解码所有地区；不能为了包上限把内容删成空城 |

街区分块、实例化共享道具、按材质合并、距离LOD、可见性裁剪、动态角色池和区域音景是优先手段。飞行会看见大片屋海，远处仍保留完整三维轮廓；地面近景不能只为一个机位成立。包、GPU资源和帧时间分别测量。

## 11. 正式整合之前及之后的验收关口

**G0 总体设计与资源准备（当前阶段）：** 内容族无遗漏、各区体验清楚、资产合同/尺度/技术路径明确；每项来源有实际证据与取得状态，核心缺口有明确补齐方式。若核心模型仍只剩一张图或未取得的账号链接，就继续做资源取得与原型设计，不能批量整合进正式全城。

**G1 资产试片：** 一套完整店铺/退廊、小龙+车、男女与店主、柳树+岸石、完整画舫在同一尺度/光照中通过。灰模、四面、俯视、近景表情、动作、真实碰撞数据和目标预算均检查；先看主形是否正确，不靠陈设/滤镜遮盖。

**G2 三段实景：** 市集街段、宫殿视点及可登临路线、曲江岸/桥/亭/停泊船各有完整前中后景与生活活动。与三张认可概念按接近构图比较至少：龙与成人尺度、完整建筑形体、檐下纵深、人物剪裁/脸、树冠/岸线、材质/明暗、人群经营关系。至少一张侧后与空中图防止单镜头造景。

**G3 全城推广：** G2通过的类型扩展到其他坊巷，逐区检查差异、连续可达、飞行屋海与远近切换。不得把全城完成缩成三段样片，也不得重新随机铺旧模型。

**G4 产品完成：** 三种移动/相机/上下船/探索/存档/声音/昼夜/触摸完整；适用真机浏览器、静态入口与离线包实测；按各区运行截图判断美术，无明显代用品/穿插/空壳/重复拼贴。软件渲染功能通过与最终视觉/真机性能分开结论。

当前G0框架与扩展候选记录已形成，**关键成品源取得及模型设计未齐，尚未放行正式整合**；G1已有木构研究试片，但不代表G1全资产或最终美术通过。下一步集中校准新增小龙/画舫设计、取得唐服可编辑来源、完成建筑类型选型与原件，避免把时间重新花在扩大旧城市和重复调后处理上。
